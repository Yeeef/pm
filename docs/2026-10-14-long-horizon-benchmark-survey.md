# Public benchmarks for a with-pm vs without-pm comparison

Surveyed 2026-10-14. Numbers come only from the linked source; "not recorded" means none was found. Estimates are labelled as such and give their basis.

## Question

Which public benchmarks of long-horizon agent work can show pm's effect, with the same model, the same runtime (Claude Code or Codex CLI) and the same budget, with pm as the only difference? pm's levers are the work store (tasks, holders, dependencies), the records (sprint frame with Goal/Scope/Done when, decisions, findings, design pages), the session-start injection of `pm show`, the Stop hook, task claims across concurrent sessions, and state handoff across sessions and context resets. A benchmark can show an effect only if its tasks span long enough, or enough sessions or agents, for those levers to matter.

## Candidates

Likely effect: H, M or L, with the reason. "CC" = Claude Code; "Codex" = Codex CLI. "Harbor" = the Terminal-Bench task/agent framework; its built-in `claude-code` and `codex` agents run the CLIs headless inside the task container.

## Prior work on scaffolds

Deltas are as reported; "pp" = percentage points.

- **Context files (AGENTS.md / CLAUDE.md), arXiv 2602.11988 (ICLR 2026).** CC + Sonnet 4.5, Codex + GPT-5.2 / GPT-5.1 mini, Qwen Code, on SWE-bench Lite and 138 new issues: LLM-generated context files lowered success by ~3% and raised cost by >20%; developer-written files raised success by ~4% and cost by up to 19%. The closest published analogue to "inject project memory at session start"; it says extra context can hurt. https://arxiv.org/abs/2602.11988
- **Harness ablations, arXiv 2609.20804.** SWE-bench Verified and Terminal-Bench 2.1, 176 matched settings. Managed vs unmanaged context: +35.7 / +15.9 / +5.5 / +2.7 pp on SWE-bench Verified at 32k / 64k / 96k / 128k budgets; +9.5 / +7.5 / +4.8 / +2.8 pp on Terminal-Bench. An explicit plan at 128k: Nemotron-3 30B +11.6 pp, but −0.4 to −2.6 pp for the stronger models, with cost changes from −$1.51 to +$0.09 per task. Reading: planning scaffolds help weak models and save cost for strong ones on short tasks. https://arxiv.org/abs/2609.20804
- **SlopCodeBench prompt ablations.** `plan_first` and `anti_slop` prompts lowered initial verbosity and erosion but not the degradation slope, and did not raise pass rate significantly; `anti_slop` raised GPT-5.4's cost per run by 47.9% ($304 to $450). Harness-version changes moved pass rate by <5 pp. https://arxiv.org/abs/2603.24755
- **SWE-Marathon context findings.** Context replay was ~99.5% of tokens; same-model token use varied up to 12× by scaffold; the lowest-token quintile passed 11.3% vs the highest 8.3%; Terminus-2 trials that compacted passed 0/71 vs 8.9% without. Correlations only, no ablation. https://arxiv.org/abs/2606.07682
- **Same model, different harness (Terminal-Bench 2.0).** GPT-5: Codex CLI 49.6% vs Terminus 2 35.2% (+14.4 pp); Opus 4.5: Terminus 2 57.8% vs CC 52.1%; Sonnet 4.5: four harnesses within 2.7 pp; Gemini 2.5 Pro: Terminus 2 32.6% vs OpenHands 15.7%. Sets the scale of harness effects that a pm effect competes with. https://arxiv.org/abs/2601.11868
- **Persistence scaffold (PaperBench).** o1: IterativeAgent 24.4% vs BasicAgent 13.2% (+11.2 pp), where IterativeAgent stops the model ending early. The nearest analogue to pm's Stop hook. https://arxiv.org/abs/2504.01848
- **Agent scaffold on MLE-bench.** GPT-4o any-medal rate: AIDE 8.7%, OpenHands 4.4%, MLAB 0.8%; o1-preview + AIDE 16.9% at pass@1, 34.1% at pass@8. https://arxiv.org/abs/2410.07095
- **Multi-agent coordination (CooperBench).** Two cooperating agents reach ~25% (GPT-5, Sonnet 4.5), about half of solo success; success fell from 68.6% (2 agents) to 46.5% (3) to 30.0% (4) in a 46-task test; the message channel did not raise success significantly but cut naive merge conflicts. Evidence that unstructured coordination fails, and an opening for claims and dependencies. https://arxiv.org/abs/2601.13295
- **Memory modules (MemoryArena).** Mean all-task success: long context ~0.15, external memory (Letta, Mem0, Mirix, ReasoningBank) ~0.13, RAG ~0.18 (averages read off Table 3). https://arxiv.org/abs/2602.16313
- **Anthropic memory tool + context editing.** Internal 100-turn agentic web-search eval: +39% with both, +29% with context editing alone, 84% fewer tokens. Vendor-internal, not reproducible. https://www.anthropic.com/news/context-management
- **Anthropic multi-agent research system.** Opus 4 lead with Sonnet 4 subagents beat single-agent Opus 4 by 90.2% on an internal research eval, at ~15× chat tokens; on BrowseComp, token usage alone explained 80% of performance variance. Vendor-internal. https://www.anthropic.com/engineering/built-multi-agent-research-system
- **Anthropic long-running harness (initializer agent, `claude-progress.txt`, feature list, git commits per session).** The pattern closest to pm's handoff; reports no success rates, only a ">200 features" example. https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- **Agent Workflow Memory.** +24.6% and +51.1% relative success on Mind2Web (step-wise) and WebArena over the prior best method. https://arxiv.org/abs/2409.07429
- **Agentic Context Engineering (evolving playbook).** +10.6% on agent benchmarks (AppWorld) and +8.6% on finance over strong baselines. https://arxiv.org/abs/2510.04618
- **Cost scale reference (HAL).** 21,730 rollouts over 9 models and 9 benchmarks cost ~$40,000 in total. https://arxiv.org/abs/2510.11977

## Shortlist

1. **SWE-Marathon.** Its horizon (2–10 h agent time, 40–400 expert hours) is the one pm is built for. CC and Codex are its native agents through Harbor. It is public under Apache-2.0. Its measured failure modes (31.4% timeout, 7.6% premature termination, compaction correlated with failure) are the ones pm's tracking, Stop hook and handoff target. Forced context resets can be added without changing the tasks, which makes handoff the measured variable.
2. **SlopCodeBench.** The only coding benchmark whose session boundaries are part of the task design: each checkpoint is a fresh container in which only the working directory carries over, which is where pm's store lives. CC and Codex run natively. A run is cheap ($323 for Opus 4.6). It also measures code erosion, which pm's design pages and decisions could plausibly reduce. The risk: a planning prompt did not move its pass rate.
3. **Long-Horizon-Terminal-Bench.** Its dense subtask reward gives more statistical power per dollar than binary pass rates, and runs are ~85 min at ~$10 per task. 79% of its failures are timeouts, so it tests whether pm's tracking speeds long single-session work. Its weakness: no session boundary, so handoff goes unused. CooperBench is the follow-up for claims across concurrent sessions, once its harness is ported to CC.

## Recommendation

**First benchmark: SWE-Marathon (v1.1 task set, pinned commit).** It is the only public benchmark where tasks outlast a context window and a session on both runtimes, and its failure taxonomy names what pm targets.

Design:

| Item | Choice |
|---|---|
| Arms | A: stock CC, one session to the task's time limit (the benchmark's standard condition; anchors to the leaderboard). B: stock CC with forced resets: the session is killed every R minutes and restarted with the same task prompt; only the repo carries over, and the agent may keep any notes file it likes (prompted to keep a progress file, as in Anthropic's long-running harness). C: CC + pm with the same forced resets. Optional D: CC + pm with no resets, to separate tracking and the Stop hook from handoff. |
| Held equal | Model and version, CC version, reasoning effort, task image (pm binary present in every arm, initialised only in C/D), per-task wall-clock limit (the benchmark's), internet policy, Modal hardware (no GPU auto-upgrade), reset interval R, and the prompt length: C's instruction to use pm is matched in A/B by an equal-length neutral instruction. Report tokens and dollars per arm; cap each trial at the same dollar budget. |
| How pm is introduced | In the image build: install the pinned pm release, create a local bare origin, `pm init` in the task repo (records branch, hooks, service). Then one project and one sprint whose Goal and Done when restate the task instruction and verifier, so the session-start injection of `pm show` carries the plan from the first reset onward. The agent opens tasks and claims them itself. Owner-facing mechanisms (needs, PR review, the owner-request judge) must be configured so that they never block an unattended run; see Open questions. |
| Reset interval | R = 60 min as a starting point: a 2–10 h limit then gives 2–10 sessions per trial. Pin R before the main run; do not tune it on the main runs. |
| Sample size | 20 tasks × 5 trials × 3 arms = 300 trials (matches the paper's 5 trials per task). With pass rates near 0.3, 100 trials per arm give a minimum detectable difference of ~18 pp (α = 0.05 two-sided, 80% power, ignoring task clustering: 2.8 × √(2 × 0.21 / 100)). 10 trials per task bring it to ~13 pp at twice the cost. Analyse paired by task, using a task-level bootstrap or a mixed-effects logistic model. |
| Metric | Primary: pass@1 from the official verifier, B vs C (handoff), plus A vs C reported as-is. Secondary: failure class (timeout, premature termination, implementation failure, reward hacking) on the paper's taxonomy; tokens and dollars per pass; sessions used. |
| Pilot | 4 tasks × 2 trials × 3 arms (24 trials) to show that pm's service starts in the Modal sandbox, its hooks fire under CC's headless mode, and resets restore state, before the main run. |

Cost estimate (an estimate, not measured):

- **Per trial (API):** ~$5 at the paper's median of 7.6M tokens and ~$20 at its mean of 27.2M tokens, on Opus 4.7/4.8 prices ($0.50/MTok cache read, $25/MTok output, $6.25/MTok cache write). This assumes ~99.5% of tokens are replayed context billed as cache reads and 0.5% are output, as the paper measured across all scaffolds; the CC-specific split is not recorded.
- **Per comparison:** 300 trials ≈ $1.5k–$6k API, plus the pilot (~$0.1–0.5k). pm's Stop-hook judge runs extra `claude -p` calls whose cost is not recorded.
- **Sandbox compute:** 300 trials × 2–10 h = 600–3,000 Modal container-hours, some on GPU for the ML tasks. The price is not recorded here. The paper warns that individual trials can cost hundreds of dollars, so the upper bound is set by the heavy tail.
- **Prices:** https://platform.claude.com/docs/en/about-claude/pricing

A cheap second check is SlopCodeBench, with 2 arms (stock CC vs CC + pm) × 3 full runs ≈ 6 × $323 ≈ $1.9k at Opus 4.6's reported cost, before pm overhead. It needs no artificial resets.

## Open questions

- Do CC's SessionStart and Stop hooks, and Codex's equivalents, fire in the headless mode Harbor uses (`claude -p`, `codex exec`)? If not, pm's injection and Stop hook are absent and the C arm only has the CLI. Check in the pilot.
- pm needs a git remote, a background service and a records branch. Does the service survive Harbor/Modal's process model and a forced session kill without manual `pm service restart`?
- pm's owner mechanisms (needs, the PR-review gate on sprint close, the owner-request judge blocking asks) assume a human owner. A benchmark run needs a defined unattended mode, or the agent may stall or burn turns on the Stop hook. Is that a pm config option, or a benchmark-specific prompt?
- Does the forced-reset design count as a fair test? Arm A must be reported alongside it. If C beats B but not A, the claim narrows to "pm reduces the cost of resets", not "pm raises the score".
- The arXiv 2602.11988 result (context files cost +20% and can lower success) predicts a cost penalty for pm's injected `pm show` and `prime.md` text. Measure tokens per trial in every arm.
- Not verified: CC as agent on LHTB, MLE-bench, PaperBench, Commit0, CodeClash, CooperBench; the tau2-bench task counts; the SWE-Marathon v1.1 per-configuration leaderboard (the site is JavaScript-rendered and was not read; secondary sources disagree); per-task partial reward in SWE-Marathon's verifiers, which would raise statistical power over binary pass.
- CooperBench is the only public test of concurrent-agent coordination. Porting its two-agent setup from OpenHands to two CC sessions sharing one pm store would test claims and dependencies directly, at an unestimated porting cost.
